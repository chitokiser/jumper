# Jumper V10 인증 및 가입 시스템 완전 분석 (Auth & Registration System)

본 문서는 현재 시스템의 회원가입, 추천인, 권한 부여 로직을 완벽하게 파악하고 향후 휴먼 에러를 방지하기 위해 작성된 가이드입니다.

## 1. 회원(User)과 Firebase Auth의 분리 구조
- **Firebase Auth (`auth.js`)**: 사용자가 구글/애플 등으로 소셜 로그인을 하면 즉시 생성되는 세션입니다.
- **Firestore DB (`users/{uid}`)**: 사용자가 `register.html`에서 이름/전화번호/권한동의를 완료해야만 만들어지는 실제 '정회원' 데이터입니다.
- **Role (권한) 검증**: 
  - 기본적으로 `users` DB의 문서를 확인하여 권한을 판별(`merchant`, `user` 등)합니다.
  - 단, **운영자는 예외**입니다. `daguri75@gmail.com`은 `users` DB 문서 생성 여부와 관계없이 코드상 무조건 최고 권한(`admin`)을 즉시 부여받습니다.

## 2. 관리자 "기존 데이터 리셋" 오해의 원인과 해결
- **발생 이유:** 최고관리자(`daguri75`)는 권한이 예외적으로 자동 부여되므로 굳이 `register.html`을 제출하지 않아도 시스템을 쓸 수 있었습니다. 하지만 헤더의 '정회원 가입' 버튼은 "DB에 `users` 문서가 있는가"만 단순 확인하도록 코딩되어 있어서, 관리자에게 지속적으로 "너는 아직 가입하지 않았다"며 해당 버튼을 띄웠고, 이를 누른 관리자는 회원 기록이 모두 삭제되었다고 오해할 수밖에 없었습니다.
- **해결 방안:** 관리자에게는 DB 존재 여부와 상관없이 '정회원 가입' 배너를 원천 차단하고 완전한 정회원 뱃지만 띄우도록 헤더 로직(`header-auth.js`)을 영구 수정했습니다.

## 3. 회원가입 폼 오진입 문제 방지 (구형 회원 데이터 호환)
- **발생 이유:** 과거에 가입한 유저는 DB에 `agreeTerms = true`라는 약관 동의 필드가 누락되어 있었습니다. 최근 프론트엔드가 이 필드를 필수값으로 체크하도록 변경되면서, 옛날 회원들도 미가입자로 튕겨내버리는 심각한 로직 상충이 있었습니다.
- **해결 방안:** `agreeTerms` 필드가 없어도 `users` 문서 자체가 존재하면 "이미 완료된 정회원"으로 인정하도록 `register.js`의 안전망 코드를 완화했습니다. 더 이상 예전 회원들이 새롭게 가입 창을 마주할 일이 없습니다.

## 4. 추천인 UID -> 이메일 전환 (`register.html`)
- 스마트 컨트랙트 및 웹3 요소가 축소/제거됨에 따라 난해한 UID 대신 직관적인 메일로 추천인(Mentor) 모델을 변경했습니다.
- 입력창 Placeholder와 하단의 힌트 안내문까지 모두 "Email"로 동기화 완료 후 빈칸일 시 `daguri75@gmail.com`이 자동 주입되도록 프론트엔드 제출 프로세스에 방어 코드를 신설했습니다.

---

> 이 분석과 조치를 통해 현 프로젝트의 가장 큰 모순(UI 표시 권한과 DB 실존 권한의 충돌)을 완전하게 해소했습니다.
