# 에이전트(AI) 작업 원칙 및 메모 (AGENT_RULES.md)
이 파일은 프로젝트 작업 전 항상 숙지해야 할 중요한 컨벤션 및 요구사항을 기록합니다.

## 1. 언어 정책
* **모든 마크다운(.md) 파일(task.md, implementation_plan.md, 각종 설계 문서 등)은 반드시 한국어로 작성합니다.**
* 유저와의 커뮤니케이션 또한 한국어를 최우선으로 사용합니다.

## 2. 블록체인/온체인 기능 사용 절대 금지 (완전 제거)
* **어떤 경우에도 온체인(블록체인, Web3, ethers.js, 스마트 컨트랙트) 코드를 새로 작성하거나 유지해서는 안 됩니다. 기존의 온체인 코드는 발견하는 즉시 모두 걷어냅니다.**
* 사용자의 잔액(포인트/VND)은 Firestore를 통해 직접 관리하며, 모든 데이터는 순수 파이어베이스 환경에서 처리합니다.
* 유저 식별 및 추천인 코드는 지갑 주소(`wallet.address`)가 아닌 파이어베이스 고유 ID(`user.uid`)만을 사용합니다.

## 3. 잭팟/가맹점 수수료 분배 로직 (가맹점 결제 시)
* 가맹점 수수료율(feeBps)에 따른 수수료 중:
    - 20%: 추천인(멘토)
    - 10%: 추천인의 추천인(그랜드 멘토)
    - 30%: 잭팟 풀에 적립 (`jackpot_config/current`)
    - 40%: 플랫폼 수익 (추천인이 없을 경우 남는 지분도 플랫폼이 흡수)

## 4. K-MOA 재화(단위) 용어 원칙 ★필독★
* **KM (KRW-Moa)**
  - 실제 결제 및 정산에 사용되는 **현금성 재화 (Money)**입니다. (기존 KRW/VND 현금 역할을 대체함)
  - Firebase 필드: 주로 `pointBalanceVnd` 로 저장하고 관리합니다 (명칭은 호환성을 위해 Vnd로 두되, 화면 표시는 무조건 **KM** 기호 사용).
* **Point (포인트 / EXP)**
  - 보상, 잭팟(Jackpot), 경험치, 퀘스트 용도로 사용되는 **비현금성 재화**입니다. (기존 Hex 및 Wei의 역할을 대체함)
  - Firebase 필드: 주로 `pointBalance` (`users` 컬렉션), `jackpotAccPoints` (`jackpot_config` 컬렉션) 등으로 관리합니다.
  - **주의:** 즉석 잭팟(Jackpot) 당첨 시스템에 누적되고 출력되는 단위는 무조건 **Point (포인트)**여야 합니다. KM이 아닙니다!

## 5. UI 데이터 바인딩 원칙 (제로섬 경제)
* 메인 페이지나 대시보드의 데이터(예: 잭팟 누적금액, 유저 잔고 등)는 **반드시** Firebase 문서(`jackpot_config`, `users` 등)를 기준으로 렌더링해야 합니다. 
* 어떠한 경우에도 외부 API(예: Railway 서버), 블록체인 RPC 호출 등을 통해 허수 수치를 가져오거나 임의의 숫자 값을 강제로 하드코딩하지 않습니다.

## 6. 테스트/배포 프로세스 원칙 (Git 연동)
* **어떤 프론트엔드 작업(.html, .js 등)이든 완료 즉시 반드시 `git push`를 실행하여 Netlify에 자동 배포(빌드)되도록 해야 합니다.** 
* 모바일 등 외부 환경에서 유저(대표님)가 실시간으로 테스트하기 위해서는 로컬 서버만 띄워두는 것으로는 부족하며, 무조건 Git 배포가 선행되어야 함을 절대 잊지 마세요.

## 7. 법적 규제 준수 및 한도 모니터링 (전자금융거래법)
* K-moa의 KM 결제 모델은 한국의 **「전자금융거래법상 선불전자지급수단」**에 해당할 소지가 매우 높습니다.
* 현재 선불전자지급수단업 등록 면제 조건인 **'미상환 발행잔액 30억 원 미만' 및 '연간 총발행액 500억 원 미만'**을 철저히 준수해야 초기 사업 전개가 가능합니다.
* 따라서 관리자와 시스템 UI에서 표시되는 시스템 총 잔고(Total Circulation)는 단순히 '보안용'뿐만 아니라 **원화(KRW) 기준 한도 모니터링 수단**이므로, 반드시 '1 KM = 1 원' 기준으로 표기하고 VND를 참고용으로 부기해야 합니다.
